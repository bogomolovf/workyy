# 🚀 Полное руководство по работе с Cursor AI в команде Workyy

## 📋 Что было настроено

Проект **workyy-fullproject-stable** полностью подготовлен для эффективной командной разработки с использованием Cursor AI. Настроена инфраструктура для работы команды из 3 разработчиков, где каждый выступает одновременно как архитектор, промпт-инженер и оператор множественных ИИ-агентов.

## 🎯 Структура настроек

### 1. Правила проекта (`.cursorrules`)

Файл в корне проекта, который Cursor автоматически читает. Содержит:

- Архитектурные принципы
- Стиль кода
- Git workflow
- Процессы разработки
- Требования к тестированию

### 2. База знаний (`.cursor/knowledge/`)

Централизованная база знаний проекта:

- **architecture.md** - Архитектура системы, компоненты, технологии
- **patterns.md** - Паттерны кода, примеры, best practices
- **decisions.md** - Архитектурные решения (ADR), важные выборы
- **onboarding.md** - Руководство для новых разработчиков

### 3. Команды (`.cursor/commands/`)

Команды Cursor доступные через префикс `/`:

**Агентские команды** (активируют специализированных агентов):

- **developer.md** ⭐ - Универсальный агент-разработчик
- **code-reviewer.md** - Агент для код-ревью
- **test-generator.md** - Агент для создания тестов
- **migration-helper.md** - Агент для работы с миграциями БД

**Команды задач** (выполняют конкретные задачи):

- **fix-bug.md** ⭐ - Исправление багов
- **develop-feature.md** ⭐ - Разработка новых фич
- **refactor.md** ⭐ - Рефакторинг кода
- **code-review.md** ⭐ - Код-ревью
- **review-pr.md** - Проверка Pull Request
- **create-test.md** - Создание тестов
- И другие (14 команд всего)

### 4. Хранилище промптов (`.cursor/prompts/`)

Папка для хранения хороших промптов, которые команда хочет сохранить для будущего использования.

### 5. Документация процессов

- **TEAM_WORKFLOW.md** - Полное руководство по командной работе
- **CURSOR_SETUP.md** - Детальная настройка Cursor
- **QUICK_START.md** - Быстрый старт (5 минут)

## 🚀 Быстрый старт

### Для новых разработчиков

1. **Установи Cursor**

   ```bash
   # Скачай с cursor.com
   # Установи последнюю версию
   ```

2. **Открой проект**

   ```bash
   cd workyy-fullproject-stable
   cursor .
   ```

3. **Изучи документацию**
   - Прочитай `CURSOR_SETUP.md`
   - Изучи `.cursor/knowledge/onboarding.md`
   - Прочитай `.cursor/TEAM_WORKFLOW.md`

4. **Проверь команды**
   - Команды уже настроены в `.cursor/commands/`
   - Settings → Rules and Commands → "Import Claude Commands" должно быть включено
   - Команды появятся в разделе "Project Commands"

5. **Начни работу**
   - Используй Cursor Ask для изучения проекта
   - Используй команды через префикс `/` в чате
   - Активируй агентов для специализированных задач

## 📖 Как использовать систему

### Ежедневный workflow

#### Утро: Синхронизация

```bash
git checkout main
git pull
pnpm install
```

Используй Cursor Ask:

```
"Покажи что изменилось в main за последние коммиты"
```

#### Работа над задачей

1. **Планирование** (Ask):

   ```
   "Как работает [компонент]?"
   "Где находится [функциональность]?"
   ```

2. **Разработка** (Agent, Ctrl+I):

   ```
   /develop-feature

   Название фичи: [НАЗВАНИЕ]
   Контекст задачи: [ОПИСАНИЕ]
   Требования: [СПИСОК]
   ```

   Или активируй агента:

   ```
   /developer

   Создай [фича]: [ОПИСАНИЕ]
   ```

3. **Тестирование** (Test Generator Agent):

   ```
   /test-generator
   "Создай тесты для [компонент]"
   ```

4. **Проверка** (Code Reviewer Agent):
   ```
   /code-reviewer
   "/review-pr для проверки моих изменений"
   ```

#### Вечер: Коммит и PR

```bash
git add .
git commit -m "feat(web): add user profile"
git push origin feature/my-task
```

### Пользовательские команды

Используй команды через префикс `/` в чате Cursor:

- `/review-pr` - Проверка Pull Request
- `/create-test` - Создание тестов
- `/check-architecture` - Проверка соответствия архитектуре
- `/resolve-conflict` - Разрешение конфликтов Git
- `/prepare-prod` - Подготовка кода для продакшна

### Специализированные агенты

#### Code Reviewer Agent

Для проведения тщательного код-ревью:

```
/code-reviewer

Проверь PR #123:
- Особое внимание на безопасность
- Проверь производительность
```

#### Test Generator Agent

Для создания качественных тестов:

```
/test-generator

Создай тесты для apps/realtime-server/src/services/boardService.ts:
- Покрой все сценарии
- Включи edge cases
```

#### Migration Helper Agent

Для работы с миграциями БД:

```
/migration-helper

Проверь миграцию 20240101_add_description:
- Безопасность
- Обратная совместимость
- Откат
```

## 🎓 Промпт-инжиниринг

### Структура хорошего промпта

1. **Контекст** - Что нужно сделать
2. **Требования** - Конкретные требования
3. **Шаги** - Пошаговые инструкции
4. **Примеры** - Ссылки на существующий код
5. **Ограничения** - Что нельзя делать

### Используй команды

Используй команды Cursor для основных задач:

- **Новая фича** → `/develop-feature`
- **Исправление бага** → `/fix-bug`
- **Рефакторинг** → `/refactor`
- **Код-ревью** → `/code-review`

Или активируй агента и опиши задачу:

- **Разработка** → `/developer`
- **Код-ревью** → `/code-reviewer`
- **Тесты** → `/test-generator`

### Примеры

✅ **Хороший промпт:**

```
Создай компонент BoardList:
1. Изучи существующие компоненты в apps/web/src/components/
2. Следуй паттернам из .cursor/knowledge/patterns.md
3. Используй TypeScript строгие типы
4. Добавь тесты используя Test Generator Agent
5. Проверь что линтер проходит
```

❌ **Плохой промпт:**

```
Создай компонент
```

## 🤝 Командная работа

### Code Review процесс

1. **Разработчик** создает PR
   - Использует Code Reviewer Agent для самопроверки
   - Исправляет замечания

2. **Коллега** ревьюит
   - Активирует Code Reviewer Agent
   - Проверяет код по чек-листу

3. **После апрува** - мердж в main

### Синхронизация знаний

1. **Экспортируй важные чаты**
   - После сложных решений
   - После изучения нового кода
   - После решения проблем

2. **Обновляй базу знаний**
   - Добавляй в `.cursor/knowledge/`
   - Обновляй `decisions.md` при архитектурных решениях

3. **Делитесь промптами**
   - Сохраняйте полезные промпты в `.cursor/prompts/`
   - Команда может добавлять туда хорошие промпты для будущего использования

### Еженедельные синхронизации

- **Code Review Session** - Групповой ревью через Cursor
- **Архитектурный ревью** - Обсуждение ADR через Cursor Ask
- **Обновление документации** - Экспорт чатов в базу знаний

## 🔄 Параллельная работа с агентами

Вы можете работать с несколькими агентами одновременно:

1. **Открой несколько чатов Cursor**
   - Один для Code Reviewer
   - Один для Test Generator
   - Один для основной разработки

2. **Используй разные режимы**
   - **Agent** для генерации кода
   - **Ask** для изучения кода
   - **Manual** для точного контроля

3. **Экспортируй важные чаты**
   - Сохраняй в `.cursor/knowledge/`
   - Используй для будущих задач

## 🚨 Частые проблемы и решения

### Агент генерирует неправильный код

**Решение:**

- Будь более конкретным в промпте
- Указывай примеры из существующего кода
- Используй команды из `.cursor/commands/` (через префикс `/`)

### Конфликты при слиянии

**Решение:**

```
/resolve-conflict для файла [название]
```

Или используй Agent:

```
"Помоги разрешить конфликт в [файл], сохрани функциональность обеих веток"
```

### Не понимаю как работает код

**Решение:**

```
Используй Cursor Ask:
"Объясни как работает [компонент]"
"Покажи где используется [функция]"
"Какие зависимости у [модуля]"
```

# Сводка чата для составления промпта (отправить в ChatGPT)

Ниже — контекст и пожелания. **Задача для ChatGPT:** составить один чёткий, подробный промпт для другого ИИ-агента (Cursor/другой ассистент), чтобы тот переделал Hero-превью на лендинге Workyy: переделал или сделал с нуля карточки Рисование, AI, Голосовые, Коллаборация, Загрузка файлов, и исправил отображение SQL на весь экран.

---

## О чём был чат

**Проект:** лендинг Workyy (Vite + React, `apps/landing`). Секция Hero с превью продукта: сетка карточек (SQL, Python, Chart, Коллаборация, Рисование, Голосовые, Загрузка файлов, AI). По клику карточка раскрывается в оверлей с демо и списком «Что делает этот виджет».

**Что делали в чате:**

1. Добавляли/улучшали анимации для голосовых (процесс записи), загрузки файлов (презентация + открытие как книжка, слайды про китов), AI (появление строк саммари).
2. Рисование: сначала path «Workyy»/«Walkie» с рисованием и стиранием по path, потом перешли на текст «Workyy» стандартным шрифтом + два `clip-path` (появление слева направо = «рисование», исчезновение = «стирание») + визуал ластика, движущегося слева направо.
3. В контент добавлены bullets для блоков Voice, Files, AI (список «Что делает этот виджет» на EN/RU).
4. Составляли описание «бага/задачи» и делали минимальное исправление (добавление визуала ластика в DrawingDemo).

**Итог:** пользователю не нравится, как реализованы карточки для рисования, AI, голосовых, коллаборации и загрузки файлов. Нужна переделка или реализация с нуля. Также нужно сделать так, чтобы SQL был на весь экран, а не только в левой части.

---

## Где лежит код

- **Hero (разметка, выбор карточки, оверлей):** `apps/landing/src/components/Hero.tsx`
- **Все демо (SQL, Python, Chart, Collab, Drawing, Voice, Files, AI):** `apps/landing/src/components/HeroPreviewDemos.tsx`
- **Тексты и bullets (EN/RU):** `apps/landing/src/data/content.ts` — `content.home.heroPreview`, в т.ч. `collab.blocks` с `title`, `description`, `bullets` для voice/files/ai.

**Текущая вёрстка Hero:**

- На больших экранах: две колонки — слева копирайт (заголовок, описание, кнопки), справа превью.
- Превью: стеклянная карточка `wy-glass` с `max-w-md aspect-[4/3]`. Внутри либо сетка 4×2 кнопок, либо оверлей с заголовком, демо-компонентом и списком «Что делает этот виджет».
- Для sql/python/chart область демо ограничена по высоте (`min-h-[72px] flex items-center`). SQL демо — компактный блок с запросом и таблицей.

**Что имеется в виду под «SQL на весь экран»:** сейчас весь Hero (и превью) ограничен по ширине (контейнер `max-w-6xl`, превью `max-w-md`), и SQL показывается только в правой колонке в узкой карточке. Нужно: когда открыта карточка SQL (или превью в целом?), демо SQL занимало весь экран / всю доступную область, а не только левую или правую часть.

## Что именно не нравится (карточки)

Пользователь явно сказал:

- **Не нравятся** реализации карточек для: **рисования**, **AI**, **голосовых**, **коллаборации**, **загрузки файлов**.
- Хочет, чтобы другой агент **переделал** это, **что-то удалил**, **что-то сделал с нуля**.

То есть не точечные правки, а переосмысление:

- **Рисование** — сейчас: текст «Workyy» + clip-path «рисование/стирание» + движущийся ластик. Можно полностью заменить концепцией и реализацией.
- **AI** — сейчас: блок «AI summary» с тремя строками, появляющимися по очереди. Можно переделать или сделать с нуля.
- **Голосовые** — сейчас: «Recording...», красная точка, волна из полосок с рандомной высотой. Можно переделать или сделать с нуля.
- **Коллаборация** — сейчас: текст + сетка из 4 блоков (Drawing, Voice, File uploads, AI) с заголовком и описанием. Можно переделать или сделать с нуля.
- **Загрузка файлов** — сейчас: этапы (файл → прогресс-бар → «Opening...» → слайд), затем «книжка» с перелистыванием слайдов про китов. Можно переделать или сделать с нуля.

## Технические ограничения и договорённости

- Лендинг: Vite + React, Tailwind, без тяжёлых зависимостей продукта (Yjs, perfect-freehand и т.д. не тащить).
- Учитывать `prefers-reduced-motion`: при включённой настройке отключать или упрощать анимации.
- Двуязычность: EN/RU из `content.ts`, не хардкодить строки в компонентах.
- Стили: использовать CSS-переменные темы (`--text`, `--border`, `--accent-cyan` и т.д.).

## Что нужно от ChatGPT

Составь **один промпт** для ИИ-агента (Cursor или аналог), который будет править код. В промпте должно быть чётко и подробно:

1. **Контекст:** лендинг Workyy, Hero, превью в правой колонке, карточки SQL/Python/Chart/Collab/Drawing/Voice/Files/AI, оверлей с демо и списком «Что делает этот виджет».
2. **Задачи по карточкам:** переделать или сделать с нуля карточки **Рисование**, **AI**, **Голосовые**, **Коллаборация**, **Загрузка файлов** — с указанием, что текущая реализация не устраивает и нужна новая концепция/дизайн/анимации (агент может предложить свои идеи в духе продукта).
3. **SQL на весь экран:** когда открыта карточка SQL (или при необходимости — всё превью), демо SQL должно занимать весь экран или всю доступную область, а не только левую/правую часть; описать в промпте желаемое поведение (например: «при раскрытии SQL оверлей на весь viewport» или «превью-фрейм на всю ширину при SQL»).
4. **Файлы для правок:** явно перечислить `Hero.tsx`, `HeroPreviewDemos.tsx`, при необходимости `content.ts`.
5. **Ограничения:** не ломать двуязычность, учитывать reduce-motion, не добавлять тяжёлые зависимости лендинга.
6. **Формат ответа агента:** что именно агент должен сделать (например: изменить компоненты, предложить макет в виде текста/списка, затем реализовать).

Сводка готова для копирования и отправки в ChatGPT. После ответа ChatGPT полученный промпт можно вставить в чат с Cursor/другим агентом для выполнения переделки.

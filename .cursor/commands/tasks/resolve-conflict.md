# Resolve Conflict

Помощь в разрешении конфликтов слияния Git с сохранением функциональности обеих веток.

## Prompt

Помоги разрешить конфликт слияния Git с сохранением функциональности обеих веток.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали задачи пользователя - не теряй контекст
- Работай автономно до полного разрешения конфликта
- Изучи обе версии кода через codebase_search
- Сохрани функциональность из обеих веток

## Процесс разрешения конфликта

### Шаг 1: Понимание контекста

**Сохрани ВСЕ детали:**

- Какие файлы имеют конфликты
- Какие ветки сливаются
- Какая функциональность важна из каждой ветки
- Любые специфические требования

### Шаг 2: Анализ обеих версий

**Изучи обе версии:**

- Используй codebase_search для понимания контекста изменений
- Пойми что делает каждая версия
- Определи какие изменения важны из каждой ветки
- Проверь связанные файлы и зависимости

**Примеры поисков:**

```
codebase_search: "How is this functionality used in the codebase?"
codebase_search: "What are the dependencies of this code?"
codebase_search: "How does this relate to other parts of the system?"
```

### Шаг 3: Разрешение конфликта

**Приоритеты:**

- Сохранить функциональность из обеих веток
- Более свежие изменения имеют приоритет, но важная логика из обеих версий должна быть сохранена
- Код должен соответствовать стилю проекта (.cursorrules)
- Решение должно быть понятным и поддерживаемым

**Стратегия:**

1. Проанализируй обе версии кода
2. Определи что из каждой версии важно сохранить
3. Предложи оптимальное решение объединяющее обе версии
4. Сохрани функциональность обеих веток
5. Убедись что решение не ломает тесты
6. Проверь что код соответствует стилю проекта (.cursorrules)

### Шаг 4: Проверка после разрешения

**После разрешения:**

- Проверь что код компилируется
- Убедись что тесты проходят
- Проверь что нет синтаксических ошибок
- Убедись что логика корректна
- Проверь что все зависимости на месте
- Убедись что код соответствует стандартам проекта

## Готов к работе

Помоги разрешить конфликт слияния. Я:

1. Сохраню ВСЕ детали твоей задачи
2. Изучу обе версии через codebase_search
3. Предложу оптимальное решение сохраняющее функциональность обеих веток
4. Проверю что решение работает корректно
5. Завершу работу только когда конфликт полностью разрешен

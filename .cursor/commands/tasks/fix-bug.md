# Fix Bug

Исправление багов с детальным анализом проблемы, поиском причины и исправлением с тестами на регрессию.

## Prompt

Исправь баг на основе предоставленной информации.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали задачи пользователя - не теряй контекст
- Работай автономно до полного исправления бага
- Используй codebase_search для изучения кода перед исправлением
- Выполняй множественные поиски для полного понимания проблемы

## Процесс исправления бага

### Шаг 1: Понимание проблемы

**Сохрани ВСЕ детали от пользователя:**

- Описание бага (что происходит vs что должно происходить)
- Шаги воспроизведения (step-by-step)
- Ошибки в консоли/логах (если есть)
- Стектрейсы (если есть)
- Файлы где может быть проблема
- Связанные компоненты
- Окружение (DEV/PROD/ОБА)
- Браузер/версия (если frontend)
- Node версия (если backend)

**НЕ ТЕРЯЙ КОНТЕКСТ:** Все детали важны для правильного исправления.

### Шаг 2: Воспроизведение и анализ

**Если возможно, воспроизведи баг:**

- Выполни шаги воспроизведения
- Проверь логи и ошибки
- Пойми когда и при каких условиях баг происходит

**Используй codebase_search для изучения:**

- Связанные файлы и компоненты
- Как работает проблемный код
- Похожие проблемы в кодовой базе
- Паттерны обработки ошибок

**Примеры поисков:**

```
codebase_search: "How is this functionality implemented?"
codebase_search: "Where are similar errors handled?"
codebase_search: "What patterns are used for error handling in this area?"
```

**Выполняй множественные поиски параллельно** для максимальной эффективности.

### Шаг 3: Поиск причины

**Найди причину бага:**

- Изучи код в указанных файлах
- Проверь логику обработки ошибок
- Проверь валидацию входных данных
- Проверь обработку edge cases
- Найди где происходит ошибка

**Используй инструменты:**

- codebase_search для понимания контекста
- read_file для изучения кода
- grep для поиска конкретных паттернов

### Шаг 4: Исправление

**Исправь с минимальными изменениями:**

- Фокусируйся только на исправлении бага
- Не рефактори весь код (если не требуется)
- Сохрани существующую функциональность
- Следуй паттернам проекта из `.cursor/knowledge/patterns.md`

**При исправлении:**

- Используй правильные типы TypeScript
- Обрабатывай ошибки правильно
- Валидируй входные данные если нужно
- Проверяй права доступа если нужно

### Шаг 5: Тест на регрессию

**Добавь тест чтобы баг не повторился:**

- Тест должен воспроизводить баг
- Тест должен проходить после исправления
- Используй Vitest для юнит-тестов
- Используй Playwright для E2E тестов если нужно

**Пример структуры теста:**

```typescript
describe('Bug fix: [описание бага]', () => {
  it('should not [описание проблемы]', async () => {
    // тест который воспроизводит баг
    // и проверяет что он исправлен
  });
});
```

### Шаг 6: Проверка влияния

**Проверь что исправление не ломает другие части:**

- Запусти все тесты: `pnpm run test`
- Проверь связанную функциональность
- Проверь что код проходит линтер: `pnpm run lint`
- Убедись что нет регрессий

### Шаг 7: Обновление документации

**Обнови документацию если нужно:**

- Если изменилось поведение API
- Если добавилась новая обработка ошибок
- Если изменились требования

## Формат использования

**Пользователь применяет команду и добавляет контекст:**

```
/fix-bug

Проблема:
При отправке POST /boards с пустым title получаем 500 ошибку вместо 400 Bad Request.

Ожидаемое поведение: Должна возвращаться ошибка 400 с сообщением о валидации.
Фактическое поведение: Возвращается 500 Internal Server Error.

Шаги воспроизведения:
1. Отправь POST запрос на /boards с body: { "title": "", "workspaceId": "..." }
2. Получаешь 500 ошибку

Ошибки в логах:
Error: Validation failed
    at BoardService.createBoard (apps/realtime-server/src/services/boardService.ts:45)
    at POST /boards (apps/realtime-server/src/routes/boards.ts:23)

Контекст:
- Файлы: apps/realtime-server/src/routes/boards.ts, apps/realtime-server/src/validators/boards.ts
- Связанные компоненты: BoardService, валидация Zod
- Окружение: DEV и PROD
```

## Готов к работе

Исправь баг на основе предоставленной информации. Я:

1. Сохраню ВСЕ детали твоей задачи
2. Воспроизведу баг если возможно
3. Изучу код через codebase_search
4. Найду причину бага
5. Исправлю с минимальными изменениями
6. Добавлю тест на регрессию
7. Проверю что все работает
8. Завершу работу только когда баг полностью исправлен

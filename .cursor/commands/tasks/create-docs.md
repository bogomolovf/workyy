# Create Documentation

Создание и обновление документации для кода, API и проекта.

## Prompt

Создай или обнови документацию для текущего кода с учетом всех требований проекта.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали задачи пользователя - не теряй контекст
- Работай автономно до полного завершения создания документации
- Изучи существующую документацию перед созданием новой
- Используй codebase_search для понимания стиля документации

## Процесс создания документации

### Шаг 1: Понимание задачи

**Сохрани ВСЕ детали:**

- Какой код нужно задокументировать
- Какой тип документации нужен (JSDoc, API docs, README)
- Какие примеры нужны
- Любые специфические требования

### Шаг 2: Изучение существующей документации

**Используй codebase_search для изучения:**

- Как организована документация в проекте
- Какой стиль используется
- Какие примеры уже есть
- Структура API документации

**Примеры поисков:**

```
codebase_search: "How is API documentation structured in this project?"
codebase_search: "What style is used for JSDoc comments?"
codebase_search: "How are code examples formatted in documentation?"
```

### Шаг 3: Создание документации

**JSDoc комментарии:**

- Описание функции/класса
- Параметры с типами и описанием
- Возвращаемое значение
- Примеры использования
- @throws для исключений
- @see для ссылок на связанный код

**Формат JSDoc:**

```typescript
/**
 * Описание функции
 *
 * @param {Type} param - Описание параметра
 * @returns {ReturnType} Описание возвращаемого значения
 * @throws {ErrorType} Когда выбрасывается исключение
 *
 * @example
 * const result = functionName(param);
 */
```

**API документация:**

- Обновить docs/api/openapi.yaml если новый endpoint
- Описание endpoints, параметров, ответов
- Примеры запросов/ответов
- Коды ошибок
- Схемы валидации

**README:**

- Обновить если новая функциональность
- Добавить примеры использования
- Обновить список зависимостей если нужно
- Обновить инструкции по установке/использованию

**Примеры:**

- Примеры использования API
- Примеры использования компонентов
- Примеры конфигурации
- Примеры типичных сценариев

### Шаг 4: Проверка

**Перед завершением:**

- ✅ Документация актуальна
- ✅ Примеры работают
- ✅ Понятно для новых разработчиков
- ✅ Соответствует стилю существующей документации
- ✅ Все публичные API задокументированы
- ✅ Нет устаревшей информации

## Готов к работе

Создай документацию для кода. Я:

1. Сохраню ВСЕ детали твоей задачи
2. Изучу существующую документацию через codebase_search
3. Создам/обновлю документацию с учетом стиля проекта
4. Добавлю примеры использования
5. Завершу работу только когда документация полностью готова

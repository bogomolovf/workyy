# Search Web

Поиск информации из опенсорс источников для реализации фичи. Команда собирает референсы, примеры кода, документацию и best practices, которые затем используются командой develop-feature для разработки.

## Prompt

Найди информацию из опенсорс источников для реализации описанной фичи.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали описания фичи - не теряй контекст
- Выполняй множественные поисковые запросы параллельно для максимальной эффективности
- Фокусируйся на опенсорс решениях, библиотеках, примерах кода
- Структурируй результаты для удобного использования командой develop-feature
- Сохраняй референсы с URL и кратким описанием

## Контекст проекта (кратко)

**Workyy** — браузерная платформа аналитики на бесконечном холсте с SQL/Python узлами и реалтайм коллаборацией.

**Архитектура:**

- `apps/web` - Next.js 14+ (App Router), React, ReactFlow, Zustand
- `apps/realtime-server` - Fastify, y-websocket, Prisma, PostgreSQL
- `packages/core-domain` - Доменные схемы
- `packages/dag-executor` - Исполнитель DAG

**Технологический стек:**

- Frontend: React, Next.js, TypeScript, ReactFlow, tldraw, Zustand
- Backend: Fastify, Prisma, PostgreSQL, y-websocket
- Realtime: Yjs, WebSocket
- Execution: DuckDB-WASM (SQL), Pyodide (Python)

**Подробнее:** См. `.cursor/commands/agents/developer-agent.md` для полного контекста.

## Процесс поиска информации

### Шаг 1: Анализ описания фичи

**Изучи описание фичи:**

1. **Основная функциональность:**
   - Что нужно реализовать?
   - Какие технологии задействованы?
   - Какие паттерны могут быть полезны?

2. **Ключевые слова для поиска:**
   - Названия технологий (React, Next.js, Fastify, Prisma и т.д.)
   - Концепции (realtime collaboration, DAG execution, WebSocket и т.д.)
   - Типы компонентов (node editor, canvas, data visualization и т.д.)

3. **Что искать:**
   - Опенсорс библиотеки и решения
   - Примеры кода и реализации
   - Документация и best practices
   - Похожие проекты и case studies
   - Статьи и туториалы

**Сохрани ВСЕ детали от пользователя:**
- Название фичи и её цель
- Контекст задачи
- Технические требования
- Ограничения и особенности
- Ожидаемый результат

### Шаг 2: Формулирование поисковых запросов

**Создай множественные поисковые запросы:**

1. **Общие запросы по фиче:**
   ```
   "[название фичи] implementation [технология]"
   "[концепция] best practices [технология]"
   ```

2. **Запросы по библиотекам:**
   ```
   "[библиотека] documentation examples"
   "[библиотека] [use case] implementation"
   ```

3. **Запросы по паттернам:**
   ```
   "[паттерн] [технология] example code"
   "[архитектурный паттерн] [контекст]"
   ```

4. **Запросы по похожим проектам:**
   ```
   "[похожий проект] [технология] open source"
   "[use case] [технология] github"
   ```

**Примеры хороших запросов:**

```
"React Flow node editor implementation examples"
"Next.js 14 App Router realtime collaboration patterns"
"Fastify WebSocket authentication best practices"
"Yjs collaborative editing examples TypeScript"
"DuckDB WASM browser execution patterns"
"Zustand state management DAG execution"
```

**Выполняй поиски параллельно** для максимальной эффективности.

### Шаг 3: Выполнение поиска

**Используй web_search для каждого запроса:**

1. **Выполняй множественные поиски одновременно:**
   - Используй `web_search` для каждого сформулированного запроса
   - Не жди результатов одного запроса перед запуском следующего
   - Параллелизуй независимые запросы (запускай несколько web_search одновременно)

2. **Анализируй результаты:**
   - Оценивай релевантность каждого результата
   - Отбирай наиболее полезные источники (минимум 5-10 релевантных референсов)
   - Обращай внимание на опенсорс репозитории (GitHub) - они наиболее полезны
   - Приоритизируй актуальную документацию и примеры кода
   - Игнорируй устаревшие источники (старые версии библиотек)

3. **Извлекай полезную информацию:**
   - Примеры кода и snippets
   - API документация и типы
   - Best practices и паттерны
   - Архитектурные решения
   - Известные проблемы и их решения
   - Информацию о совместимости с технологиями проекта

**Важно:** Выполняй достаточно поисков, чтобы собрать разнообразную и полезную информацию. Обычно требуется 5-10 поисковых запросов для хорошего покрытия темы.

### Шаг 4: Структурирование результатов

**Организуй найденную информацию:**

1. **Категории информации:**
   - **Библиотеки и инструменты** - опенсорс пакеты, которые можно использовать
   - **Примеры кода** - готовые реализации и snippets
   - **Документация** - официальная документация и гайды
   - **Best practices** - рекомендации и паттерны
   - **Похожие проекты** - референсы на похожие реализации
   - **Статьи и туториалы** - обучающие материалы

2. **Формат референсов:**

   Для каждого референса укажи:
   - **Название/Заголовок**
   - **URL** (если доступен)
   - **Тип** (library, example, documentation, article, github repo)
   - **Краткое описание** (что полезного содержит)
   - **Релевантность** (высокая/средняя/низкая)
   - **Ключевые моменты** (что конкретно полезно)

3. **Пример структурированного результата:**

   ```markdown
   ## Референсы для реализации фичи

   ### Библиотеки и инструменты

   #### [Название библиотеки]
   - **URL**: https://github.com/...
   - **Тип**: library
   - **Описание**: [Краткое описание]
   - **Релевантность**: высокая
   - **Ключевые моменты**:
     - Поддержка [функциональность]
     - TypeScript типы
     - Активная поддержка

   ### Примеры кода

   #### [Название примера]
   - **URL**: https://example.com/...
   - **Тип**: example
   - **Описание**: [Краткое описание]
   - **Релевантность**: высокая
   - **Ключевые моменты**:
     - Показывает как [что-то сделать]
     - Использует [технологии]
   ```

### Шаг 5: Сохранение результатов

**Сохрани результаты для использования командой develop-feature:**

1. **Создай файл с референсами:**
   - Сохрани в `.cursor/knowledge/references-[feature-slug].md`
   - Используй slug из названия фичи (lowercase, дефисы вместо пробелов)
   - Используй структурированный формат Markdown
   - Включи все важные детали

2. **Формат файла:**

   ```markdown
   # Референсы для: [Название фичи]

   ## Описание фичи
   [Описание из запроса пользователя]

   ## Референсы

   [Структурированные референсы из Шага 4]

   ## Рекомендации

   [Выводы и рекомендации на основе найденной информации]

   ## Следующие шаги

   [Что нужно сделать дальше для реализации]
   ```

3. **Используй write tool для сохранения:**
   - Создай файл через `write` tool
   - Убедись что файл сохранен в правильной директории
   - Проверь форматирование Markdown

4. **Укажи путь к файлу:**
   - Сообщи пользователю где сохранены референсы
   - Предложи использовать команду develop-feature с этими референсами
   - Покажи пример использования: "Используй команду `/develop-feature` и укажи путь к референсам: `.cursor/knowledge/references-[feature-slug].md`"

### Шаг 6: Формирование рекомендаций

**На основе найденной информации сформулируй рекомендации:**

1. **Рекомендуемые библиотеки:**
   - Какие библиотеки стоит использовать
   - Почему они подходят
   - Как их интегрировать

2. **Архитектурные решения:**
   - Какие паттерны применить
   - Как структурировать код
   - Что учесть при реализации

3. **Потенциальные проблемы:**
   - Известные проблемы и их решения
   - Ограничения технологий
   - Best practices для избежания проблем

4. **Следующие шаги:**
   - Что нужно изучить дополнительно
   - Какие примеры кода использовать
   - Как интегрировать с существующим кодом

## Формат использования

**Пользователь применяет команду и добавляет описание фичи:**

### Пример 1: Поиск информации для новой фичи

```
/search-web

Название фичи: Экспорт данных из узлов в CSV

Описание:
Нужно добавить возможность экспортировать результаты выполнения SQL узлов в CSV файл. Пользователи должны иметь возможность скачать данные таблицы в CSV формате.

Требования:
1. Экспорт результатов SQL узла в CSV
2. Кнопка экспорта в UI узла
3. Поддержка больших объемов данных (streaming)
4. Правильная обработка специальных символов и кодировки

Технологии:
- Frontend: React, Next.js
- Данные: результаты из executionStore (SqlResult формат)
- Формат: CSV с UTF-8 кодировкой
```

### Пример 2: Поиск информации для интеграции библиотеки

```
/search-web

Название фичи: Интеграция библиотеки для визуализации данных

Описание:
Нужно добавить визуализацию результатов SQL узлов. Рассматриваем использование библиотеки для построения графиков и диаграмм.

Требования:
1. Библиотека должна работать в браузере
2. Поддержка TypeScript
3. Интеграция с React
4. Различные типы графиков (line, bar, pie, scatter)
5. Интерактивность (zoom, pan, tooltips)

Ограничения:
- Должна работать с DuckDB-WASM результатами
- Не должна конфликтовать с существующими зависимостями
- Размер бандла должен быть разумным
```

### Пример 3: Поиск информации для архитектурного решения

```
/search-web

Название фичи: Оптимизация производительности выполнения узлов

Описание:
Нужно оптимизировать выполнение больших DAG с множеством узлов. Текущая реализация выполняет узлы последовательно, что медленно для больших графов.

Требования:
1. Параллельное выполнение независимых узлов
2. Кэширование результатов выполнения
3. Отмена выполнения при изменении кода узла
4. Прогресс выполнения для пользователя

Технологии:
- JavaScript/TypeScript
- DAG executor (существующий пакет)
- React для UI прогресса
```

# Check Architecture

Проверка соответствия кода архитектуре проекта и принятым решениям.

## Prompt

Проверь соответствие кода архитектуре проекта Workyy и принятым решениям.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали задачи пользователя - не теряй контекст
- Работай автономно до полного завершения проверки
- Используй codebase_search для изучения архитектуры и ADR
- Выполняй множественные поиски для полного понимания

## Процесс проверки

### Шаг 1: Понимание контекста

**Сохрани ВСЕ детали:**

- Какие файлы/компоненты нужно проверить
- На что обратить особое внимание
- Какие аспекты архитектуры критичны
- Любые специфические требования

### Шаг 2: Изучение архитектуры

**Используй codebase_search для изучения:**

- ADR из `docs/architecture/adr/` - принятые архитектурные решения
- Паттерны из `.cursor/knowledge/patterns.md` - используемые паттерны
- Структура пакетов в `packages/` - доступные пакеты
- Примеры правильного использования архитектуры

**Примеры поисков:**

```
codebase_search: "What architectural decisions are documented in ADR?"
codebase_search: "How are packages from packages/ used in the codebase?"
codebase_search: "What patterns are used for API routes in Fastify?"
codebase_search: "How are Next.js App Router patterns used?"
```

**Выполняй множественные поиски параллельно** для максимальной эффективности.

### Шаг 3: Проверка соответствия

**Что проверять:**

**Использование пакетов:**

- ✅ Используются правильные пакеты (`@workyy/core-domain`, `@workyy/ui-kit`, etc.)
- ✅ Нет дублирования функциональности из пакетов
- ✅ Правильное использование алиасов импортов `@workyy/<package>`
- ✅ Нет создания новых пакетов когда можно использовать существующие

**Паттерны:**

- ✅ Следуются паттерны из `.cursor/knowledge/patterns.md`
- ✅ Next.js App Router используется правильно (Server/Client components)
- ✅ Fastify роуты следуют установленным паттернам
- ✅ Prisma запросы оптимизированы (select, нет N+1)
- ✅ React компоненты следуют паттернам проекта

**ADR (Architectural Decision Records):**

- ✅ Соответствие ADR из `docs/architecture/adr/`
- ✅ Не нарушаются принятые решения
- ✅ Новые решения документируются если нужно

**Разделение ответственности:**

- ✅ Следование SOLID принципам
- ✅ Правильное разделение на слои (routes, services, repositories)
- ✅ Нет смешивания ответственности
- ✅ Компоненты делают одну вещь хорошо

**Технологии:**

- ✅ Правильное использование Next.js App Router
- ✅ Правильное использование Fastify
- ✅ Правильное использование Prisma
- ✅ Правильное использование React паттернов

**Дублирование:**

- ✅ Нет дублирования кода
- ✅ Используются существующие утилиты
- ✅ Переиспользуются компоненты из `packages/ui-kit`

### Шаг 4: Форматирование ответа

**Структурируй ответ:**

1. **Критические проблемы (блокеры)**
   - Нарушения архитектуры которые нужно исправить
   - Указывай конкретные файлы и строки: `filepath:line_number`
   - Объясняй почему это критично
   - Предлагай как исправить

2. **Важные замечания (нужно исправить)**
   - Проблемы которые важно исправить
   - Указывай конкретные места: `filepath:line_number`
   - Объясняй влияние на архитектуру
   - Предлагай решения

3. **Рекомендации (можно улучшить)**
   - Улучшения которые не критичны но желательны
   - Объясняй преимущества
   - Предлагай конкретные улучшения

4. **Положительные моменты (что хорошо)**
   - Что соответствует архитектуре
   - Что можно использовать как пример
   - Что правильно использует паттерны

## Готов к работе

Проверь соответствие архитектуре. Я:

1. Сохраню ВСЕ детали твоей задачи
2. Изучу архитектуру через codebase_search и чтение ADR
3. Проведу полную проверку соответствия
4. Предоставлю структурированный отчет
5. Завершу работу только когда проверка полностью завершена

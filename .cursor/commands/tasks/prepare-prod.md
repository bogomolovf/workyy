# Prepare Production

Подготовка кода для переноса в продакшн с проверкой всех критических аспектов.

## Prompt

Подготовь код для переноса в продакшн с полной проверкой всех критических аспектов.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали задачи пользователя - не теряй контекст
- Работай автономно до полного завершения подготовки
- Используй codebase_search для изучения конфигурации и зависимостей
- Проверь все аспекты перед продакшн деплоем

## Процесс подготовки

### Шаг 1: Понимание контекста

**Сохрани ВСЕ детали:**

- Какие компоненты/сервисы нужно подготовить
- Какие окружения затронуты
- Какие специфические требования
- План деплоя если есть

### Шаг 2: Изучение конфигурации

**Используй codebase_search для изучения:**

- Как настроены окружения
- Какие env переменные используются
- Как настроен Docker
- Какие зависимости используются

**Примеры поисков:**

```
codebase_search: "How are environment variables configured for production?"
codebase_search: "What is the Docker configuration for deployment?"
codebase_search: "How are database migrations handled in production?"
```

### Шаг 3: Детальная проверка

**Окружения:**

- ✅ Все env переменные вынесены в .env
- ✅ Нет хардкода конфигурации
- ✅ Правильные значения для production
- ✅ .env.example обновлен
- ✅ Нет dev значений в production конфигурации

**Зависимости:**

- ✅ Нет dev-зависимостей в production bundle
- ✅ Все зависимости актуальны и безопасны
- ✅ package.json правильно настроен
- ✅ Проверены уязвимости (npm audit)

**База данных:**

- ✅ Миграции протестированы на dev
- ✅ Есть план отката миграций
- ✅ Seed данные обновлены если нужно
- ✅ Индексы созданы для производительности
- ✅ Backup стратегия на месте

**Безопасность:**

- ✅ Нет секретов в коде
- ✅ CORS настроен правильно для production
- ✅ Rate limiting включен
- ✅ Валидация всех входных данных
- ✅ Проверка прав доступа
- ✅ HTTPS настроен
- ✅ Безопасные cookies

**Производительность:**

- ✅ Нет N+1 запросов к БД
- ✅ Используется select в Prisma
- ✅ Кэширование где нужно
- ✅ Оптимизация бандла (frontend)
- ✅ Code splitting настроен
- ✅ Ленивая загрузка компонентов

**Docker:**

- ✅ Dockerfile оптимизирован (multi-stage build)
- ✅ Правильный .dockerignore
- ✅ Минимальный размер образа
- ✅ Правильные health checks
- ✅ Правильные volumes

**Мониторинг:**

- ✅ Логирование настроено
- ✅ Health endpoints работают
- ✅ Метрики собираются
- ✅ Алерты настроены

### Шаг 4: Чек-лист деплоя

**Создай пошаговый чек-лист для деплоя:**

- Применение миграций
- Настройка env переменных
- Перезапуск сервисов
- Проверка health endpoints
- План отката
- Проверка функциональности
- Мониторинг после деплоя

## Готов к работе

Подготовь код для продакшн. Я:

1. Сохраню ВСЕ детали твоей задачи
2. Изучу конфигурацию через codebase_search
3. Проведу полную проверку всех аспектов
4. Создам чек-лист для деплоя
5. Завершу работу только когда подготовка полностью завершена

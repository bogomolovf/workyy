# Describe Bug

Анализирует контекст чата, определяет что было предпринято для исправления бага, объясняет почему это не сработало, и создает детальное описание проблемы с указанием всех связанных файлов и элементов.

## Prompt

Проанализируй историю этого чата и создай детальное описание бага/проблемы/дефектного поведения.

**КРИТИЧЕСКИ ВАЖНО:**

- Изучи ВСЮ историю чата от начала до текущего момента
- Определи что было предпринято для исправления
- Объясни почему попытки исправления не сработали
- Найди ВСЕ файлы и элементы, связанные с багом (даже косвенно)
- Создай структурированное описание для последующей обработки командой `fix-bug`

## Контекст проекта (кратко)

**Workyy** — браузерная платформа аналитики на бесконечном холсте с SQL/Python узлами и реалтайм коллаборацией.

**Архитектура:**

- `apps/web` - Next.js 14+ (App Router), React, ReactFlow, Zustand
- `apps/realtime-server` - Fastify, y-websocket, Prisma, PostgreSQL
- `packages/core-domain` - Доменные схемы
- `packages/dag-executor` - Исполнитель DAG

**Ключевые особенности:**

- Реалтайм синхронизация через Yjs (автоматическая)
- Выполнение узлов: SQL (DuckDB-WASM), Python (Pyodide) в браузере
- Execution Store (Zustand) для результатов выполнения узлов
- DAG (Directed Acyclic Graph) для зависимостей узлов

**Подробнее:** См. `.cursor/commands/agents/developer-agent.md` для полного контекста.

## Процесс анализа бага

### Шаг 1: Анализ истории чата

**Изучи всю историю чата:**

1. **Первоначальное описание проблемы:**
   - Что было описано пользователем?
   - Какое дефектное поведение наблюдалось?
   - Какие шаги воспроизведения были указаны?
   - Какой был ожидаемый результат?

2. **Предпринятые попытки исправления:**
   - Какие изменения были внесены?
   - Какие файлы были модифицированы?
   - Какие подходы были опробованы?
   - Что было добавлено/удалено/изменено?

3. **Результаты попыток:**
   - Сработало ли исправление?
   - Если нет - почему?
   - Какие ошибки появились?
   - Что изменилось в поведении?

4. **Контекст обсуждения:**
   - Какие гипотезы выдвигались?
   - Какие вопросы задавались?
   - Какая дополнительная информация была получена?

### Шаг 2: Поиск связанных файлов и элементов

**Найди ВСЕ связанные компоненты:**

1. **Прямо связанные файлы:**
   - Файлы, которые были изменены
   - Файлы, упомянутые в чате
   - Файлы с ошибками в консоли/логах

2. **Косвенно связанные файлы:**
   - Импорты измененных файлов
   - Файлы, импортирующие измененные компоненты
   - Сервисы/утилиты, используемые проблемным кодом
   - Типы и схемы, связанные с проблемой

3. **Связанные элементы системы:**
   - API endpoints (если проблема в backend)
   - React компоненты (если проблема в frontend)
   - Store состояния (Zustand stores)
   - Сервисы и утилиты
   - Типы и интерфейсы
   - Конфигурация (env, схемы БД)

**Используй codebase_search для поиска:**

```
codebase_search: "How does [проблемная функциональность] work?"
codebase_search: "Where is [затронутый компонент] used?"
codebase_search: "What files import [измененный файл]?"
```

**Используй grep для точного поиска:**

```
grep: найти все использования измененных функций/компонентов
grep: найти все импорты измененных модулей
grep: найти все места, где используются затронутые типы
```

### Шаг 3: Анализ причин неудачи

**Определи почему исправление не сработало:**

1. **Корневая причина:**
   - Была ли устранена настоящая причина бага?
   - Или исправлялись только симптомы?
   - Есть ли более глубокие проблемы в архитектуре?

2. **Побочные эффекты:**
   - Появились ли новые проблемы?
   - Нарушилась ли другая функциональность?
   - Есть ли конфликты с существующим кодом?

3. **Недостающая информация:**
   - Что не было учтено?
   - Какие зависимости не были проанализированы?
   - Какие edge cases не были покрыты?

4. **Специфика Workyy:**
   - Проблема с Yjs синхронизацией?
   - Проблема с executionStore?
   - Проблема с DAG зависимостями?
   - Проблема с выполнением узлов?

## Формат использования

**Пользователь применяет команду в чате, где уже была попытка исправления:**

```
/describe-bug
```

Команда автоматически анализирует всю историю чата и создает описание выше.

**Или с дополнительным контекстом:**

```
/describe-bug

Дополнительный контекст:
- Проблема возникла после последнего коммита
- Воспроизводится только в Chrome
- Связана с выполнением Python узлов
```

## Пример вывода

После анализа чата команда выводит детальное описание в формате выше, которое затем можно использовать с командой `/fix-bug`:

```
/fix-bug

[Вставь сюда описание бага, созданное командой describe-bug]
```

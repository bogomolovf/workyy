# Refactor

Рефакторинг кода с сохранением функциональности, улучшением читаемости и следованием паттернам проекта.

## Prompt

Проведи рефакторинг кода на основе предоставленных требований.

**КРИТИЧЕСКИ ВАЖНО:**

- Сохрани ВСЕ детали задачи пользователя - не теряй контекст
- Работай автономно до полного завершения рефакторинга
- Сохраняй всю функциональность (все тесты должны проходить)
- Используй codebase_search для изучения кода перед рефакторингом

## Процесс рефакторинга

### Шаг 1: Понимание задачи

**Сохрани ВСЕ детали от пользователя:**

- Компонент/сервис/модуль для рефакторинга
- Цель рефакторинга (что хотим улучшить)
- Текущие проблемы (конкретное описание)
- Требования к рефакторингу
- Технические детали
- Ожидаемый результат

**НЕ ТЕРЯЙ КОНТЕКСТ:** Все детали важны для правильного рефакторинга.

### Шаг 2: Изучение текущего кода

**Используй codebase_search для изучения:**

- Как используется этот код
- Какие зависимости есть
- Какие паттерны используются в похожем коде
- Существующие тесты
- Связи с другими компонентами

**Примеры поисков:**

```
codebase_search: "How is [компонент] used in the codebase?"
codebase_search: "What patterns are used for similar [тип компонента]?"
codebase_search: "How is [функциональность] implemented?"
```

**Выполняй множественные поиски параллельно** для максимальной эффективности.

**Изучи существующие тесты:**

- Пойми что тестируется
- Убедись что тесты покрывают функциональность
- Тесты помогут убедиться что ничего не сломалось

### Шаг 3: Планирование рефакторинга

**Для сложных рефакторингов используй todo_write:**

- Разбей на логические части
- Создавай атомарные задачи
- Отмечай задачи как completed после завершения

**Определи что можно улучшить:**

- Читаемость кода
- Разделение ответственности
- Удаление дублирования
- Улучшение структуры
- Оптимизация производительности (если нужно)

### Шаг 4: Рефакторинг

**При рефакторинге:**

- Сохраняй всю функциональность
- Следуй SOLID принципам
- Используй паттерны из `.cursor/knowledge/patterns.md`
- Улучшай читаемость
- Удаляй дублирование
- Выноси общие части
- Улучшай структуру

**Типичные улучшения:**

- Разбиение больших функций/компонентов на меньшие
- Вынесение валидации в отдельные функции
- Вынесение логики в кастомные хуки (React)
- Использование мемоизации где нужно (React)
- Унификация обработки ошибок
- Улучшение типизации

### Шаг 5: Обновление тестов

**Обнови тесты если нужно:**

- Если изменилась структура кода
- Если добавились новые функции
- Убедись что все тесты проходят
- Добавь тесты для новой функциональности если появилась

### Шаг 6: Проверка

**Перед завершением:**

- Проверь что все тесты проходят: `pnpm run test`
- Проверь что линтер проходит: `pnpm run lint`
- Проверь производительность (если критично)
- Убедись что функциональность сохранена
- Убедись что нет регрессий

## Формат использования

**Пользователь применяет команду и добавляет контекст:**

```
/refactor

Компонент: BoardService

Цель рефакторинга:
Улучшить читаемость и разделить ответственность. Метод createBoard слишком большой и смешивает бизнес-логику с работой с БД.

Текущие проблемы:
1. Метод createBoard слишком большой (100+ строк)
2. Смешана бизнес-логика и работа с БД
3. Нет обработки ошибок
4. Сложно тестировать (много зависимостей)
5. Дублирование кода валидации

Требования:
1. Сохрани всю функциональность (все тесты должны проходить)
2. Раздели на меньшие методы (каждый метод делает одну вещь)
3. Вынеси валидацию в отдельный метод
4. Добавь обработку ошибок
5. Сделай код более тестируемым
6. Следуй паттернам из .cursor/knowledge/patterns.md

Технические детали:
- Используй паттерн Repository для работы с БД
- Вынеси валидацию в отдельный класс/функцию
- Используй типы из @workyy/core-domain
- Следуй SOLID принципам

Ожидаемый результат:
- Метод createBoard разбит на меньшие методы
- Код более читаемый и тестируемый
- Все тесты проходят
- Функциональность сохранена
```

## Готов к работе

Проведи рефакторинг на основе предоставленных требований. Я:

1. Сохраню ВСЕ детали твоей задачи
2. Изучу текущий код через codebase_search
3. Изучу существующие тесты
4. Спланирую рефакторинг
5. Проведу рефакторинг с сохранением функциональности
6. Обновлю тесты если нужно
7. Проверю что все работает
8. Завершу работу только когда рефакторинг полностью завершен

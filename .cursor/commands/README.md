# Cursor Commands

Этот каталог содержит пользовательские команды для Cursor AI, доступные всей команде через префикс `/` в чате.

## 📁 Структура

```
.cursor/commands/
├── agents/          # Команды-агенты (активируют специализированных агентов)
│   ├── developer.md        # ⭐ Универсальный агент-разработчик
│   ├── code-reviewer.md
│   ├── test-generator.md
│   └── migration-helper.md
├── tasks/           # Чистые команды (выполняют конкретные задачи)
│   ├── fix-bug.md           # ⭐ Исправление багов
│   ├── develop-feature.md   # ⭐ Разработка новых фич
│   ├── refactor.md          # ⭐ Рефакторинг кода
│   ├── code-review.md       # ⭐ Код-ревью
│   ├── review-pr.md
│   ├── create-test.md
│   ├── check-architecture.md
│   └── ... (14 команд всего)
└── README.md        # Этот файл
```

## 🎯 Как это работает

### Пайплайн использования

1. **Активация агента** (опционально):

   ```
   /code-reviewer
   ```

   → Активирует Code Reviewer Agent в текущем чате

2. **Использование команд**:

   ```
   /review-pr
   /check-security
   /create-test
   ```

   → Команды выполняются с учетом активированного агента (если есть)

3. **Или используйте команды независимо**:
   ```
   /review-pr
   ```
   → Команда работает и без активации агента

## 🤖 Агентские команды (agents/)

Эти команды активируют специализированных агентов в текущем чате.

### `/developer` ⭐ (Основной агент)

Активирует универсального Developer Agent для разработки функционала.

**Используй для:**

- Разработки новых фич
- Рефакторинга кода
- Исправления багов
- Любых задач разработки

**Просто опиши задачу:**

```
/developer

Создай компонент для отображения списка досок:
- Должен показывать все доски пользователя
- С возможностью поиска и фильтрации
- С пагинацией для больших списков
```

### `/code-reviewer`

Активирует Code Reviewer Agent для детального код-ревью.

**После активации можно использовать:**

- `/review-pr` - Проверка Pull Request
- `/check-security` - Проверка безопасности
- `/analyze-performance` - Анализ производительности
- `/check-architecture` - Проверка архитектуры
- `/suggest-improvements` - Предложения по улучшению

**Или просто опишите задачу:**

```
/code-reviewer

Проверь файл apps/realtime-server/src/routes/boards.ts
```

### `/test-generator`

Активирует Test Generator Agent для создания качественных тестов.

**После активации можно использовать:**

- `/create-test` - Создание тестов для текущего файла

**Или просто опишите задачу:**

```
/test-generator

Создай E2E тест для создания доски
```

### `/migration-helper`

Активирует Migration Helper Agent для работы с миграциями БД.

**После активации можно описать задачу:**

```
/migration-helper

Создай миграцию для добавления поля "description" в таблицу Board
```

## 📋 Команды задач (tasks/)

Эти команды выполняют конкретные задачи. Могут использоваться с агентами или независимо.

### `/fix-bug` ⭐

Исправление багов с детальным анализом проблемы, поиском причины и исправлением с тестами на регрессию.

**Использование:**

```
/fix-bug

Проблема:
[Описание проблемы, шаги воспроизведения, логи, стектрейсы]

Контекст:
[Файлы, компоненты, окружение]
```

### `/develop-feature` ⭐

Разработка новой функциональности с изучением существующих паттернов, созданием компонентов, написанием тестов.

**Использование:**

```
/develop-feature

Название фичи: [НАЗВАНИЕ]

Контекст задачи:
[Что нужно сделать]

Требования:
1. [Требование 1]
2. [Требование 2]
...
```

### `/refactor` ⭐

Рефакторинг кода с сохранением функциональности, улучшением читаемости и следованием паттернам проекта.

**Использование:**

```
/refactor

Компонент: [КОМПОНЕНТ]

Цель рефакторинга:
[Что хотим улучшить]

Текущие проблемы:
1. [Проблема 1]
2. [Проблема 2]
...
```

### `/code-review`

Проведение код-ревью с проверкой всех аспектов: стиль кода, безопасность, производительность, архитектура.

**Использование:**

```
/code-review

Ветка: [ВЕТКА/PR]

Проверь следующее:
1. ✅ Соответствие стилю кода
2. ✅ Безопасность
...
```

### `/review-pr`

Проверка Pull Request на соответствие стандартам, безопасность и качество кода.

### `/create-test`

Создание тестов для текущего файла с покрытием основных сценариев и edge cases.

### `/check-architecture`

Проверка соответствия кода архитектуре проекта и принятым решениям.

### `/check-security`

Проверка безопасности кода на наличие уязвимостей и соблюдение best practices.

### `/analyze-performance`

Анализ производительности кода с выявлением проблем и предложением оптимизаций.

### `/resolve-conflict`

Помощь в разрешении конфликтов слияния Git с сохранением функциональности обеих веток.

### `/prepare-prod`

Подготовка кода для переноса в продакшн с проверкой всех критических аспектов.

### `/create-docs`

Создание и обновление документации для кода, API и проекта.

### `/suggest-improvements`

Предложение улучшений для кода: рефакторинг, оптимизация, улучшение читаемости.

### `/explain-code`

Детальное объяснение как работает код: логика, поток выполнения, зависимости.

## 💡 Примеры использования

### Пример 1: Исправление бага

```
/fix-bug

Проблема:
При отправке POST /boards с пустым title получаем 500 ошибку вместо 400 Bad Request.

Ожидаемое поведение: Должна возвращаться ошибка 400 с сообщением о валидации.
Фактическое поведение: Возвращается 500 Internal Server Error.

Шаги воспроизведения:
1. Отправь POST запрос на /boards с body: { "title": "", "workspaceId": "..." }
2. Получаешь 500 ошибку

Ошибки в логах:
Error: Validation failed
    at BoardService.createBoard (apps/realtime-server/src/services/boardService.ts:45)

Контекст:
- Файлы: apps/realtime-server/src/routes/boards.ts, apps/realtime-server/src/validators/boards.ts
- Окружение: DEV и PROD
```

### Пример 2: Разработка новой фичи

```
/develop-feature

Название фичи: Удаление доски

Контекст задачи:
Нужно добавить возможность удалять доски через API.

Требования:
1. Endpoint DELETE /boards/:id
2. Проверка прав доступа (только владелец или админ)
3. Каскадное удаление связанных узлов и соединений
4. Аудит событие при удалении
```

### Пример 3: Рефакторинг

```
/refactor

Компонент: BoardService

Цель рефакторинга:
Улучшить читаемость и разделить ответственность.

Текущие проблемы:
1. Метод createBoard слишком большой (100+ строк)
2. Смешана бизнес-логика и работа с БД
3. Нет обработки ошибок
```

### Пример 4: Разработка с агентом

```
# Активируй Developer Agent
/developer

# Опиши задачу
Создай API endpoint DELETE /boards/:id:
- Проверка прав доступа (только владелец или админ)
- Каскадное удаление связанных узлов и соединений
- Аудит событие при удалении
- Используй паттерны из .cursor/knowledge/patterns.md
- Добавь тесты
```

### Пример 2: Агент + Команда

```
# В новом чате:
/code-reviewer

# Затем используй команды:
/review-pr
Проверь мои изменения в feature/add-user-profile

/check-security
Проверь безопасность кода
```

### Пример 3: Команда без агента

```
/review-pr

Проверь мои изменения
```

### Пример 4: Агент + Описание задачи

```
/code-reviewer

Проверь файл apps/realtime-server/src/routes/boards.ts:
- Фокус на обработку ошибок
- Проверь валидацию входных данных
```

### Пример 5: Несколько агентов в разных чатах

**Чат 1:**

```
/code-reviewer
/review-pr
```

**Чат 2:**

```
/test-generator
/create-test
```

## 🔧 Настройка в Cursor

Команды автоматически загружаются из этой директории если в настройках Cursor включено:

- Settings → Rules and Commands → "Import Claude Commands" (должно быть включено)

## 📝 Добавление новых команд

### Добавление агентской команды

1. Создайте файл в `.cursor/commands/agents/[название].md`
2. Используйте формат:

   ```markdown
   # Название агента

   Описание агента.

   ## Prompt

   Ты [название] Agent для проекта Workyy.

   [Промпт агента]

   **Готов к работе!**
   ```

### Добавление команды задачи

1. Создайте файл в `.cursor/commands/tasks/[название].md`
2. Используйте формат:

   ```markdown
   # Название команды

   Описание команды.

   ## Prompt

   [Инструкции для выполнения задачи]
   ```

## ✅ Примечания

- Команды доступны всем разработчикам проекта
- Команды автоматически синхронизируются через Git
- Агенты можно использовать независимо или в комбинации с командами
- Обновляйте команды по мере улучшения процессов

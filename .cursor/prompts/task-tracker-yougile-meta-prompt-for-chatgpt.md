# Мета-промпт для ChatGPT: сгенерировать промпт для Cursor AI (таск-трекер как YouGile)

Скопируй блок ниже **целиком** в ChatGPT. Попроси ответ **на русском** или **на английском** — как удобнее для передачи в Cursor.

---

## Текст для ChatGPT

Ты — продуктовый техлид и UX-редактор. Твоя задача: **написать один готовый промпт для ИИ-разработчика в Cursor**, чтобы он реализовал в продукте **таск-трекер в стиле YouGile** (канбан, спринты/итерации по желанию, задачи, подзадачи, теги, назначения, комментарии — перечисли только то, что критично для MVP, остальное — backlog).

### Контекст продукта (зафиксируй в промпте явно)

- В приложении уже есть **борды** (канва, узлы, коллаборация). Новый таск-трекер **не должен быть реализацией «ещё одного борда»** в смысле той же сущности/того же UI, что канвас-борд.
- При этом **с точки зрения пользователя** он может создаваться **«как отдельный борд»** (отдельная сущность в списке workspace, отдельный контекст работы), но **внутри это отдельный тип артефакта** (например `TaskTracker` / `Project`), а не `Board` с нодами.
- Таск-трекер открывается **отдельной вкладкой** в UI приложения (не вложенной вкладкой внутри канваса), с **собственным layout** и навигацией.
- Стек (адаптируй формулировки под это, без выдумывания конкретных файлов): monorepo, **Next.js** в `apps/web`, realtime/API в `apps/realtime-server`, общие пакеты в `packages/*`, контракты API в `docs/api/openapi.yaml`.

### Что должен содержать итоговый промпт для Cursor (обязательные разделы)

1. **Цель и границы**: что входит в MVP, что явно не делаем в первой итерации.
2. **Модель данных**: чем отличается сущность таск-трекера от канвас-борда; связь с workspace/team; идентификаторы.
3. **UX**: отдельная вкладка, маршрутизация, создание «как борд» но с типом; пустые состояния; мобильная адаптация — по минимуму.
4. **Функции MVP**: доски колонок (канбан), карточка задачи, статусы, базовые поля; синхронизация/permissions — на уровне требований, без лишней детализации, если не уверен — пометь как «уточнить у команды».
5. **Интеграция с существующим**: как не ломать текущие борды; миграции не придумывай, но опиши совместимость.
6. **Критерии готовности (acceptance)**: чеклист проверки.
7. **Риски**: путаница «борд vs таск-трекер» — как избежать в нейминге и UI.

### Формат ответа

- Выдай **один цельный промпт** для Cursor, который можно вставить в чат агента **как есть**.
- В конце добавь короткий **список открытых вопросов** (3–7 пунктов), которые команда должна закрыть до реализации.

### Стиль

- Конкретно, без воды, без маркетинга.
- Не придумывай названия эндпоинтов, если нет оснований — пиши «спроектировать по аналогии с существующими workspace/board routes».

---

## Как использовать результат

1. Вставь ответ ChatGPT в новый чат **Cursor Agent**.
2. Добавь одну строку: «Репозиторий: Workyy monorepo; сначала изучи `docs/api/openapi.yaml` и текущие роуты workspace/board, потом предложи план и минимальный diff.»
3. По открытым вопросам из хвоста — синхронизируйся с командой и обнови промпт.

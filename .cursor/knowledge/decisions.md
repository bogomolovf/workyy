# Архитектурные решения (ADR)

## Важные решения команды

### ADR-001: Использование Monorepo

**Дата**: 2024
**Статус**: Принято

**Контекст**: Нужна единая кодовая база для frontend, backend и landing.

**Решение**: Использовать pnpm workspaces для monorepo структуры.

**Последствия**:

- ✅ Общие пакеты легко переиспользовать
- ✅ Единая версия зависимостей
- ⚠️ Нужно аккуратно управлять зависимостями

### ADR-002: Next.js App Router

**Дата**: 2024
**Статус**: Принято

**Контекст**: Выбор между Pages Router и App Router для Next.js.

**Решение**: Использовать App Router для лучшей производительности и поддержки.

**Последствия**:

- ✅ Server Components по умолчанию
- ✅ Лучшая производительность
- ⚠️ Нужно явно указывать 'use client' для интерактивности

### ADR-003: y-websocket для реалтайм

**Дата**: 2024
**Статус**: Принято

**Контекст**: Нужна реалтайм синхронизация канвы между пользователями.

**Решение**: Использовать y-websocket (Yjs) для CRDT синхронизации.

**Последствия**:

- ✅ Автоматическое разрешение конфликтов
- ✅ Оптимистичные обновления
- ⚠️ Нужно понимать CRDT модель

### ADR-004: Prisma ORM

**Дата**: 2024
**Статус**: Принято

**Контекст**: Выбор ORM для работы с PostgreSQL.

**Решение**: Использовать Prisma для типобезопасности и миграций.

**Последствия**:

- ✅ Типобезопасные запросы
- ✅ Автоматические миграции
- ⚠️ Нужно генерировать клиент после изменений схемы

### ADR-005: Trunk-based Development

**Дата**: 2024
**Статус**: Принято

**Контекст**: Выбор стратегии ветвления Git.

**Решение**: Использовать trunk-based с короткоживущими feature ветками.

**Последствия**:

- ✅ Быстрый мердж в main
- ✅ Меньше конфликтов
- ⚠️ Нужна хорошая CI/CD

## Известные ограничения

1. **WebSocket соединения**: Нет автоматического переподключения при разрыве
2. **Большие доски**: Могут быть проблемы с производительностью при 100+ узлах
3. **Миграции БД**: Нужно тестировать на dev перед применением в prod

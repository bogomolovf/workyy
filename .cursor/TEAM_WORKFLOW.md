# Руководство по командной работе в Cursor AI

## 🎯 Обзор

Это руководство описывает как эффективно работать в команде из 3 разработчиков используя Cursor AI. Каждый разработчик выступает одновременно как:

- **Архитектор** - проектирует решения
- **Промпт-инженер** - создает эффективные промпты
- **Оператор агентов** - управляет множественными ИИ-агентами

## 📋 Структура проекта для Cursor

```
workyy-fullproject-stable/
├── .cursorrules              # Правила для ИИ (читает автоматически)
├── .cursor/
```

## 🚀 Быстрый старт

### 1. Настройка Cursor

1. **Установи последнюю версию Cursor**
   - Проверь обновления: `Help → Check for Updates`

2. **Открой проект**

   ```bash
   cd workyy-fullproject-stable
   cursor .
   ```

3. **Cursor автоматически прочитает `.cursorrules`**
   - Правила применяются ко всем сессиям ИИ

4. **Изучи базу знаний**
   - Прочитай `.cursor/knowledge/` для понимания проекта
   - Используй Cursor Ask для изучения кода

### 2. Первая задача

```bash
# 1. Синхронизация с main
git checkout main
git pull
pnpm install

# 2. Создай ветку
git checkout -b feature/my-first-task

# 3. Используй Cursor для разработки
# Открой Cursor Chat и используй команду:
/develop-feature

Название фичи: [НАЗВАНИЕ]
Контекст задачи: [ОПИСАНИЕ]
Требования: [СПИСОК]
```

### Работа над задачей

#### Шаг 1: Планирование

```
Используй Cursor Ask для изучения:
- "Как работает [компонент/сервис]?"
- "Где находится логика [функциональность]?"
- "Какие паттерны используются для [задача]?"
```

#### Шаг 2: Разработка

```
Используй команды Cursor:
1. Активируй агента если нужно: /developer, /code-reviewer, /test-generator
2. Используй команды задач: /develop-feature, /fix-bug, /refactor
3. Или опиши задачу напрямую после активации агента
4. Проверяй сгенерированный код
```

#### Шаг 3: Тестирование

```
Используй команды:
/test-generator
/create-test

Или просто:

```

#### Шаг 4: Проверка перед коммитом

```bash

"/review-pr для проверки моих изменений"
```

```
## 🤖 Работа с агентами

### Типы агентов

#### 1. Code Reviewer Agent
**Когда использовать:**
- Перед созданием PR
- При ревью кода коллег
- После больших изменений

**Как активировать:**
```

/code-reviewer

Проверь мои изменения:

- Особое внимание на [аспект]
- Проверь [конкретная вещь]

```

Или используй команды задач:
```

/code-reviewer
/review-pr
/check-security

```

#### 2. Test Generator Agent
**Когда использовать:**
- После создания нового кода
- При исправлении багов (тест на регрессию)
- Для улучшения покрытия

**Как активировать:**
```

/test-generator

Создай тесты для [файл/компонент]:

- Покрой [сценарии]
- Включи edge cases

```

Или используй команду:
```

/create-test

```

#### 3. Migration Helper Agent
**Когда использовать:**
- При работе с миграциями БД
- Перед применением миграций в prod

**Как активировать:**
```

/migration-helper

Проверь миграцию [название]:

- Безопасность
- Обратная совместимость
- Откат

```

### Параллельная работа с несколькими агентами

Вы можете работать с несколькими агентами одновременно:

1. **Открой несколько чатов Cursor**
   - Один для Code Reviewer
   - Один для Test Generator
   - Один для основной разработки

2. **Используй разные режимы**
   - Agent для генерации кода
   - Ask для изучения кода
   - Manual для точного контроля

3. **Экспортируй важные чаты**
   - Сохраняй в `.cursor/knowledge/`
   - Используй для будущих задач

## 📝 Промпт-инжиниринг

### Структура хорошего промпта

1. **Контекст**: Что нужно сделать
2. **Требования**: Конкретные требования
3. **Шаги**: Пошаговые инструкции
4. **Ограничения**: Что нельзя делать
5. **Примеры**: Ссылки на существующий код

### Использование команд

Используй команды Cursor для основных задач:

- **Новая фича**: `/develop-feature`
- **Исправление бага**: `/fix-bug`
- **Рефакторинг**: `/refactor`
- **Код-ревью**: `/code-review`

Или активируй агента и опиши задачу:
- **Разработка**: `/developer`
- **Код-ревью**: `/code-reviewer`
- **Тесты**: `/test-generator`

### Советы по промптам

✅ **Хорошо:**
- "Создай компонент BoardList следуя паттернам из apps/web/src/components/Board.tsx"
- "Исправь баг в apps/realtime-server/src/routes/boards.ts, проверь валидацию"
- "Рефакторинг BoardService, раздели на меньшие методы, сохрани функциональность"

❌ **Плохо:**
- "Сделай компонент" (слишком общо)
- "Исправь баг" (нет контекста)
- "Улучши код" (непонятно что улучшать)

## 🔍 Отслеживание задач

### GitHub Issues

1. **Создавай задачи через GitHub**
   - Используй шаблоны issues
   - Связывай с PR через `fixes #123`

2. **Используй Cursor для работы с задачами**
```

"Покажи открытые задачи из GitHub"
"Создай PR для задачи #123"

```

### Доски задач (опционально)

Если используете Linear/Jira:

1. **Настрой MCP интеграцию** (если доступно)
2. **Используй Cursor для синхронизации**
```

"Покажи мои задачи из Linear"
"Обнови статус задачи #123 на 'In Progress'"

````

### Внутренний трекинг

Создай файл `.cursor/tasks.md` для отслеживания:

```markdown
# Текущие задачи команды

## В работе
- [ ] #123 - Добавить шаринг досок (Иван)
- [ ] #124 - Оптимизация запросов БД (Мария)

## В ревью
- [ ] #122 - Новый тип узла (Петр)

## Запланировано
- [ ] #125 - Рефакторинг BoardService
````

## 👥 Взаимодействие в команде

### Code Review процесс

1. **Разработчик создает PR**

   ```bash
   # Использует команду для самопроверки
   /review-pr
   ```

2. **Коллега ревьюит**

   ```
   /code-reviewer

   Проверь PR #123:
   - Особое внимание на безопасность
   - Проверь производительность
   ```

   Или используй команду:

   ```
   /code-review

   Ветка: feature/add-board-sharing
   Проверь следующее:
   - Безопасность
   - Производительность
   ```

3. **После апрува - мердж**
   ```bash
   git checkout main
   git pull
   # Код готов
   ```

### Синхронизация знаний

1. **Экспортируй важные чаты**
   - После сложных решений
   - После изучения нового кода
   - После решения проблем

2. **Обновляй базу знаний**
   - Добавляй в `.cursor/knowledge/`
   - Обновляй `decisions.md` при архитектурных решениях

3. **Делитесь промптами**
   - Сохраняйте полезные промпты в `.cursor/prompts/`
   - Команда может добавлять туда хорошие промпты для будущего использования
   - Комментируйте что работает хорошо

### Еженедельные синхронизации

1. **Code Review Session**
   - Групповой ревью через Cursor
   - Обсуждение паттернов

2. **Архитектурный ревью**
   - Обсуждение ADR через Cursor Ask
   - Обновление `decisions.md`

3. **Обновление документации**
   - Экспорт чатов в базу знаний
   - Обновление промптов

## 🚨 Частые проблемы и решения

### Проблема: Агент генерирует неправильный код

**Решение:**

- Будь более конкретным в промпте
- Указывай примеры из существующего кода
- Используй команды из `.cursor/commands/` (через префикс `/`)

### Проблема: Конфликты при слиянии

**Решение:**

```
/resolve-conflict для файла [название]

Или используй Agent:
"Помоги разрешить конфликт в [файл], сохрани функциональность обеих веток"
```

### Проблема: Не понимаю как работает код

**Решение:**

```
Используй Cursor Ask:
"Объясни как работает [компонент/сервис]"
"Покажи где используется [функция]"
"Какие зависимости у [модуля]"
```

# Описание бага: Невозможность ввода размера шрифта с клавиатуры

## Краткое резюме

Пользователь не может ввести произвольный размер шрифта с клавиатуры в input поле размера шрифта в `TextToolbar`. При попытке ввода символы не появляются или фокус теряется. Также требуется автоматическое применение размера ко всему тексту при изменении.

## Дефектное поведение

**Что происходит:**

- При клике на input поле размера шрифта (`<input type="number">`) и попытке ввести число с клавиатуры, символы не появляются или фокус теряется
- Размер шрифта не применяется автоматически ко всему тексту при изменении через input, стрелки или выбор из dropdown
- Пользователь может выбрать размер из dropdown списка, но не может ввести произвольное значение

**Ожидаемое поведение:**

- Пользователь должен иметь возможность кликнуть на input поле и ввести любое число от 8 до 500 с клавиатуры
- При вводе числа размер должен автоматически применяться ко всему тексту в текстовом узле
- При использовании стрелок вверх/вниз размер должен применяться ко всему тексту
- При выборе размера из dropdown размер должен применяться ко всему тексту

**Фактическое поведение:**

- Input поле не принимает ввод с клавиатуры
- Размер применяется только к выделенному фрагменту текста (если есть выделение), а не ко всему тексту

## Воспроизведение

**Шаги для воспроизведения:**

## Корневая причина

### Гипотезы о корневой причине:

1. **Конфликт с `handleClickOutside` и `onInteractionEnd()`:**
   - `handleClickOutside` слушает события `click` на `document` (строка 149)
   - При клике на input может срабатывать `handleClickOutside`, который вызывает `onInteractionEnd()`
   - `onInteractionEnd()` возвращает фокус в редактор, что прерывает ввод
   - **Вероятность: Высокая**

2. **Преждевременный вызов `onInteractionEnd()` в `onChange`:**
   - В `onChange` обработчике (строки 414-420) вызывается `onInteractionEnd()` через `requestIdleCallback` или `setTimeout` с задержкой 200ms
   - Это может возвращать фокус в редактор до завершения ввода пользователем
   - **Вероятность: Высокая**

3. **Контролируемый input с частыми обновлениями:**
   - Input является контролируемым (`value={fontSize}`)
   - Если `fontSize` обновляется слишком часто (например, через `forceUpdate` каждые 100ms, строка 96-101), это может конфликтовать с вводом
   - **Вероятность: Средняя**

4. **Конфликт с глобальными обработчиками клавиатуры:**
   - В `BoardCanvas.tsx` есть глобальный обработчик `keydown` (строки 2348-2367)
   - Хотя он проверяет `isInput`, может быть проблема с определением input поля размера шрифта
   - **Вероятность: Низкая**

5. **Проблема с `onBlur` обработчиком:**
   - `onBlur` (строки 423-429) вызывает `onInteractionEnd()` через `setTimeout` с задержкой 150ms
   - Это может мешать нормальной работе input
   - **Вероятность: Средняя**

### Наиболее вероятная причина:

**Комбинация причин 1 и 2:**

1. `handleClickOutside` перехватывает клики и может вызывать `onInteractionEnd()` даже при клике на input
2. `onChange` вызывает `onInteractionEnd()` слишком рано, возвращая фокус в редактор до завершения ввода

**Почему она наиболее вероятна:**

- Input поле находится внутри `fontSizeDropdownRef` (строка 383), но сам input не защищен от `handleClickOutside`
- `handleClickOutside` проверяет только `fontSizeDropdownRef.current.contains(target)`, но не проверяет, является ли target самим input полем
- `onChange` срабатывает при каждом изменении значения, и немедленно вызывает `onInteractionEnd()`, что возвращает фокус

### Текущая структура input:

```typescript
<input
  type="number"
  value={fontSize}
  onChange={(e) => {
    // ... обработка изменения
    // ПРОБЛЕМА: вызывает onInteractionEnd() слишком рано
    onInteractionEnd();
  }}
  onBlur={(e) => {
    // ... обработка blur
    // ПРОБЛЕМА: также вызывает onInteractionEnd()
    onInteractionEnd();
  }}
  onFocus={(e) => {
    onInteractionStart();
  }}
  onMouseDown={(e) => {
    e.stopPropagation();
    onInteractionStart();
  }}
/>
```

### Рекомендуемая структура:

```typescript
const [localFontSize, setLocalFontSize] = useState(fontSize);
const fontSizeInputRef = useRef<HTMLInputElement>(null);

// Обновляем локальное состояние при изменении пропса
useEffect(() => {
  setLocalFontSize(fontSize);
}, [fontSize]);

<input
  ref={fontSizeInputRef}
  type="number"
  value={localFontSize}
  onChange={(e) => {
    const inputValue = e.target.value;
    if (inputValue === '') {
      setLocalFontSize('');
      return;
    }
    const newSize = Number(inputValue);
    if (newSize >= 8 && newSize <= 500 && !isNaN(newSize) && newSize > 0) {
      setLocalFontSize(newSize);
      // НЕ вызываем onInteractionEnd() здесь
    }
  }}
  onBlur={(e) => {
    // Применяем размер только при blur
    const newSize = Number(e.target.value);
    if (newSize >= 8 && newSize <= 500 && !isNaN(newSize) && newSize > 0) {
      onFontSizeChange(newSize);
      // Применяем размер ко всему тексту
      applyFontSizeToAllText(newSize);
      // Только теперь возвращаем фокус
      onInteractionEnd();
    } else {
      // Восстанавливаем значение если невалидное
      setLocalFontSize(fontSize);
    }
  }}
  onKeyDown={(e) => {
    if (e.key === 'Enter') {
      e.preventDefault();
      e.currentTarget.blur(); // Триггерит onBlur
    }
  }}
  onFocus={(e) => {
    onInteractionStart();
  }}
  onMouseDown={(e) => {
    e.stopPropagation();
    onInteractionStart();
  }}
/>
```

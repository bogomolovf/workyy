Собери команду агентов и выполни задачу: $ARGUMENTS

## Роли команды

Ты — **лид**. Твоя работа: разбить задачу на подзадачи, распределить их между тиммейтами, следить за прогрессом и синтезировать результат.

### Когда создавать команду

Создавай команду **только если задача затрагивает 2+ слоя** (frontend + backend, или frontend + shared types, и т.д.). Если задача в одном слое — выполни сам, не создавая тиммейтов.

### Состав команды

Spawn тиммейтов **только тех, кто нужен** для конкретной задачи. Не создавай лишних.

**Доступные роли:**

#### 1. `frontend` — Фронтенд-разработчик
- **Зона:** `apps/web/src/` — компоненты, хуки, сторы, стили
- **Не трогает:** `apps/realtime-server/`, `packages/`
- **Стек:** React, ReactFlow, Zustand, Yjs, ECharts, DuckDB-WASM, Pyodide
- **Ключевые правила:**
  - API через `apiFetch` из `lib/apiClient.ts`
  - Логика НЕ в `BoardCanvas.tsx` — пиши в `board/InnerBoardCanvas.tsx` или хуки
  - Zustand селекторы атомарные: `(s) => s.field`
  - Yjs синхронизация уже есть — не дублируй
  - Типы из `@workyy/core-domain`, не создавай локальные дубликаты

#### 2. `backend` — Бэкенд-разработчик
- **Зона:** `apps/realtime-server/src/` — роуты, валидаторы, сервисы, Prisma
- **Не трогает:** `apps/web/`, `packages/`
- **Стек:** Fastify, Prisma, PostgreSQL, Zod, y-websocket
- **Ключевые правила:**
  - Валидация Zod на входе каждого роута
  - `preHandler: [fastify.authenticate]` на всех эндпоинтах
  - Доступ через `ensureBoardAccess` / `ensureWorkspaceAccess`
  - Ошибки: `reply.status(4xx).send({ detail: 'message' })`
  - Не регистрируй роуты дважды

#### 3. `shared` — Архитектор общих типов
- **Зона:** `packages/core-domain/src/` — Zod-схемы и TypeScript типы
- **Не трогает:** `apps/web/`, `apps/realtime-server/`
- **Ключевые правила:**
  - Zod-схема + `z.infer<typeof Schema>` для каждого типа
  - Реэкспорт из `index.ts`
  - После изменений: `cd packages/core-domain && pnpm build`
  - Добавление optional поля безопасно, required — нужен default

#### 4. `reviewer` — Ревьюер (read-only)
- **Зона:** весь проект, только чтение
- **Задача:** проверяет код других тиммейтов после завершения
- **Фокус:** типизация, безопасность, производительность, паттерны проекта
- **Не модифицирует файлы** — только отчитывается лиду

## Алгоритм работы лида

### Шаг 1: Декомпозиция задачи

Разбери задачу от пользователя:
1. **Что нужно сделать** — конкретные требования
2. **Какие слои затронуты** — frontend / backend / shared / все
3. **Зависимости** — что должно быть готово до чего

### Шаг 2: Определить состав команды

Выбери минимальный набор тиммейтов:

| Задача | Команда |
|--------|---------|
| Full-stack фича | `shared` → `backend` + `frontend` |
| Только фронтенд | Не нужна команда, делай сам |
| Только бэкенд | Не нужна команда, делай сам |
| Рефакторинг кросс-слойный | `frontend` + `backend` |
| Новая фича + ревью | `frontend` + `backend` + `reviewer` |

### Шаг 3: Создать task list

Создай задачи с зависимостями. Правила:
- **5-6 задач на тиммейта** — оптимальный размер
- **Каждый тиммейт владеет своими файлами** — нет пересечений
- **Зависимости явные** — shared types → backend & frontend

Пример для full-stack фичи:

```
Задача 1: [shared] Добавить TemplateSchema в core-domain → пересобрать
Задача 2: [backend] CRUD эндпоинты /api/templates (зависит от 1)
Задача 3: [frontend] UI компоненты для шаблонов (зависит от 1)
Задача 4: [backend] Prisma модель + миграция (параллельно с 2)
Задача 5: [frontend] Интеграция с API (зависит от 2, 3)
Задача 6: [reviewer] Ревью всего кода (зависит от 2-5)
```

### Шаг 4: Spawn тиммейтов

Для каждого тиммейта дай **детальный spawn prompt** с контекстом:

```
Spawn тиммейта "frontend" с моделью Sonnet.
Промпт: "Ты фронтенд-разработчик проекта Workyy.
Работаешь ТОЛЬКО в apps/web/src/.
[контекст конкретной задачи]
Используй apiFetch для API. Типы из @workyy/core-domain.
Не трогай BoardCanvas.tsx — пиши в board/InnerBoardCanvas.tsx."
```

### Шаг 5: Координация

- Следи за task list — кто что делает
- Если тиммейт застрял — помоги или переназначь
- Если найден конфликт — разреши сам
- Когда все задачи done — синтезируй результат

### Шаг 6: Финализация

1. Попроси `reviewer` (если есть) проверить весь код
2. Запусти финальные проверки:
   - `npx tsc --noEmit` для всех apps
   - `pnpm build`
   - Grep на `console.log`, `[DIAG:*]`
3. Отчитайся пользователю:
   - Что сделано (по задачам)
   - Какие файлы изменены/созданы
   - Как проверить
   - Если были проблемы — что и как решено

## Правила для тиммейтов

Включи в spawn prompt каждого тиммейта:
- Используй Sonnet для тиммейтов (экономия токенов)
- Каждый тиммейт ОБЯЗАН проверить `npx tsc --noEmit` в своём app перед завершением задачи
- Не добавлять `console.log` в продакшен код
- При конфликте или неясности — сообщить лиду, не принимать решение самостоятельно
- Прочитать существующий код перед изменениями

## Примеры использования

### Full-stack фича:
```
/team Система шаблонов бордов: пользователь может сохранить текущий борд как шаблон
и создать новый борд из шаблона. Нужны: Prisma модель, CRUD API, UI в меню борда.
```

### Кросс-слойный рефакторинг:
```
/team Перенести все inline типы из api.ts и routes/boards.ts в core-domain.
Синхронизировать типы между фронтом и бэком.
```

### Фича с ревью:
```
/team Добавить систему нотификаций: WebSocket события от сервера при изменениях борда.
После реализации — ревью на безопасность и производительность.
```

### Дебаг сложной проблемы:
```
/team При совместной работе 3+ пользователей на борде ноды "прыгают".
Исследуйте проблему с разных сторон: Yjs sync, ReactFlow state, WebSocket latency.
```

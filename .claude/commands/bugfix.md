## Контекст проекта

**Workyy** — браузерная платформа аналитики на бесконечном холсте с SQL/Python узлами и реалтайм коллаборацией.

**Стек:** Next.js 14 + ReactFlow + Zustand + Yjs + DuckDB-WASM + Pyodide + Fastify + Prisma + PostgreSQL.

## Алгоритм отладки

### 1. Понять проблему

Извлеки из описания бага:
- **Симптомы** — что видит пользователь (ошибка, неверное поведение, пустой экран)
- **Область** — frontend / backend / realtime / shared types
- **Шаги воспроизведения** — если описаны

Если описание неполное — **спроси** у пользователя до начала работы.

### 2. Локализовать баг

**Параллельно** запусти поиск по нескольким направлениям:

1. **Grep по ключевым словам** из описания бага (имена компонентов, сообщения об ошибках, имена функций)
2. **Git log** — были ли недавние изменения в этой области (`git log --oneline -20 -- <path>`)
3. **Прочитай файлы**, которые упоминаются в описании или найдены по grep

**Определи data flow бага:** UI компонент → хук → store → API → DB (или обратно).

### 3. Сформулировать гипотезы

Создай 2-3 гипотезы, ранжированные по вероятности. Для каждой:
- Что именно может быть причиной
- Какой файл и примерно какая строка
- Как проверить

### 4. Добавить диагностику (если причина не очевидна)

Добавь targeted console.log для проверки гипотез:

```typescript
console.log('[DIAG:area] description:', variable);
```

Формат `[DIAG:area]` чтобы легко найти и убрать потом.

**Где ставить логи:**
- На входе/выходе подозрительной функции
- Перед и после трансформации данных
- В условных ветках (чтобы понять какая выполняется)

**Попроси пользователя** проверить в DevTools и сообщить результат.

### 5. Исправить

- **Минимальный фикс** — не рефактори вокруг бага, исправь только причину
- Если фикс затрагивает несколько файлов — объясни почему
- Проверь что фикс не ломает смежную функциональность

### 6. Верифицировать

1. **TypeScript**: `npx tsc --noEmit` для затронутого app
2. **Кэш**: `rm -rf apps/web/.next` (если фронтенд)
3. **Lint**: проверь что нет оставленных console.log
4. **Опиши** как проверить фикс в браузере (шаги)
5. **Укажи** какие `[DIAG:*]` логи оставлены для подтверждения (убрать после)

## Частые причины багов в этом проекте

| Симптом | Вероятная причина | Где искать |
|---------|-------------------|------------|
| `Cannot find module './106.js'` | Stale .next кэш | `rm -rf apps/web/.next` |
| Edges не соединяются | handleId на верхнем уровне вместо metadata | `useEdgesStateSynced`, `adapters.ts` |
| PlotNode пустой | Fallback chain не доходит до данных | `usePlotSnapshot`, `useFullCsvDataForPlot`, `useFullSqlDataForPlot` |
| DuckDB `duplicate table` | Таблица регистрируется повторно | `duckdbClient.ts`, SQL-нода execution |
| Бесконечный ре-рендер | Zustand selector возвращает новый объект | Проверь selector — должен возвращать примитив или stable ref |
| Yjs не синхронизируется | Provider не подключён или awareness lost | `useBoardCollaboration`, `collaborationService.ts` |
| API 403/404 | Неверный route или отсутствует authenticate | `routes/`, проверь preHandler |
| Node execution зависает | Race condition в async коде | `python.worker.ts`, `executionStore` |

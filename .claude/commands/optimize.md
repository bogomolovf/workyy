## Контекст проекта

**Workyy** — браузерная платформа аналитики. Ключевые bottleneck-области:
- ReactFlow канва с десятками нод и эджей
- Zustand stores с частыми обновлениями
- DuckDB-WASM / Pyodide execution в браузере
- Yjs realtime sync через WebSocket
- Большие CSV/SQL datasets в памяти браузера

## Алгоритм оптимизации

### 1. Определить что оптимизировать

Извлеки из запроса:
- **Что тормозит** — конкретный компонент, операция, загрузка
- **Метрика** — время рендера, время загрузки, memory usage, bundle size
- **Масштаб** — при каком объёме данных / количестве элементов проблема

Если описание неполное — **спроси** у пользователя.

### 2. Профилировать текущее состояние

**Прочитай код** и определи bottleneck:

1. **React рендеринг** — найди компоненты без memo, тяжёлые вычисления в render
2. **Store updates** — найди селекторы, возвращающие новые объекты/массивы
3. **Data processing** — найди дублирующиеся вычисления, лишние копии данных
4. **Network** — найди лишние API вызовы, отсутствие кеширования
5. **Bundle** — найди тяжёлые импорты без dynamic import

**Предложи пользователю** замерить "до" (React DevTools Profiler, Performance tab, console.time).

### 3. Спланировать оптимизации

Для каждой оптимизации укажи:
- **Что**: конкретное изменение
- **Почему**: какой bottleneck решает
- **Ожидаемый эффект**: примерная оценка улучшения
- **Риск**: может ли сломать существующую функциональность

Приоритизируй: **высокий impact + низкий риск** → сначала.

### 4. Реализовать

Применяй оптимизации из чеклиста ниже. После каждой:
- Проверь `npx tsc --noEmit`
- Убедись что функциональность сохранена

### 5. Отчёт

### Изменения
- [файл:строка] — что оптимизировано и почему

### Как замерить
- [инструкции для пользователя: React Profiler, Performance tab, console.time]

## Чеклист оптимизаций

### React / ReactFlow рендеринг

- [ ] Компоненты нод обёрнуты в `React.memo` с кастомным comparator
- [ ] Zustand селекторы возвращают примитивы или stable references (shallow compare)
- [ ] `useCallback` / `useMemo` для функций и объектов в props
- [ ] Тяжёлые списки виртуализированы (`react-window` / `@tanstack/react-virtual`)
- [ ] `nodeTypes` / `edgeTypes` определены ВНЕ компонента (стабильная ссылка)
- [ ] `onNodesChange` / `onEdgesChange` не пересоздаются каждый рендер
- [ ] Conditional rendering вместо `display: none` для тяжёлых панелей

### Zustand stores

- [ ] Селекторы атомарные: `(s) => s.value`, НЕ `(s) => ({ a: s.a, b: s.b })`
- [ ] Для составных селекторов — `useShallow` или `shallow` compare
- [ ] Actions не создают новые объекты без изменений (`if (prev === next) return`)
- [ ] Нет подписок на весь store: `useStore()` без селектора

### Данные и вычисления

- [ ] CSV/Excel парсятся однократно, результат кешируется
- [ ] DuckDB запросы дедуплицированы (нет повторной регистрации таблиц)
- [ ] Pyodide worker — один shared, не создаётся на каждый run
- [ ] Большие объекты не копируются без необходимости (`structuredClone` только когда нужен)
- [ ] Тяжёлые вычисления вынесены в Web Worker

### Сеть и загрузка

- [ ] API вызовы дедуплицированы (guard в useEffect или TanStack Query)
- [ ] WebSocket (Yjs): awareness updates throttled
- [ ] Файлы/изображения lazy-loaded
- [ ] API responses кешированы где уместно

### Bundle size

- [ ] Dynamic imports для тяжёлых зависимостей (`Pyodide`, `DuckDB`, `CodeMirror`, `ECharts`)
- [ ] Tree-shaking: нет barrel exports, тянущих весь модуль
- [ ] Нет дублирующихся зависимостей в node_modules (`pnpm why <pkg>`)

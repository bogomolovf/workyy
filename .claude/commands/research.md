Исследуй лучшие практики и референсы для реализации фичи: $ARGUMENTS

## Алгоритм

### 1. Анализ запроса

Разбери описание фичи:
- **Что** нужно реализовать
- **Какие технологии** задействованы (из стека проекта или новые)
- **Какие концепции** лежат в основе (realtime, visualization, DAG, etc.)
- **Какие ограничения** есть

### 2. Поиск референсов (параллельно)

Запусти 3-5 параллельных Agent-ов (subagent_type: Explore или general-purpose) для поиска по разным направлениям:

**Направление 1 — Опенсорс библиотеки:**
- WebSearch: "[технология] [концепция] library npm/github"
- Оцени: размер бандла, TypeScript поддержка, активность, совместимость со стеком

**Направление 2 — Примеры реализации:**
- WebSearch: "[концепция] implementation [технология] example"
- WebSearch: "[концепция] [технология] tutorial 2024 2025"
- Ищи GitHub-репозитории с похожей функциональностью

**Направление 3 — Best practices и паттерны:**
- WebSearch: "[концепция] best practices [технология]"
- WebSearch: "[концепция] architecture patterns"

**Направление 4 — Известные проблемы:**
- WebSearch: "[технология] [концепция] pitfalls common mistakes"
- WebSearch: "[библиотека] known issues performance"

**Направление 5 — Существующий код проекта:**
- Grep/Glob по кодовой базе — как похожие задачи уже решены в Workyy
- Какие паттерны использовались для аналогичной функциональности

### 3. Глубокое изучение (для топ-3 находок)

Для самых релевантных результатов:
- WebFetch документацию или README
- Изучи API, примеры кода, типы
- Проверь совместимость с нашим стеком:
  - Frontend: React, Next.js 14+, TypeScript, ReactFlow, Zustand, ECharts
  - Backend: Fastify, Prisma, PostgreSQL, y-websocket
  - Realtime: Yjs, WebSocket
  - Execution: DuckDB-WASM, Pyodide

### 4. Формирование саммари

Подготовь структурированный отчёт:

```
## Research: [Название фичи]

### Контекст
[Что нужно сделать и зачем — из запроса пользователя]

### Рекомендуемый подход
[1-2 абзаца — какой подход выбрать и почему]

### Библиотеки / Инструменты
| Название | Назначение | Bundle size | TS | Stars | Вердикт |
|----------|-----------|-------------|-----|-------|---------|
| lib-a    | ...       | ...         | ✅  | ...   | ✅ Использовать |
| lib-b    | ...       | ...         | ✅  | ...   | ⚠️ Альтернатива |

### Ключевые паттерны
- **Паттерн 1**: [описание + ссылка]
- **Паттерн 2**: [описание + ссылка]

### Примеры кода (из open source)
[Релевантные сниппеты с указанием источника]

### Как это ложится на Workyy
- Какие существующие компоненты/хуки переиспользовать
- Где разместить новый код
- Как интегрировать с executionStore / Yjs / ReactFlow

### Потенциальные проблемы
- [Проблема 1 и как избежать]
- [Проблема 2 и как избежать]

### План реализации (высокоуровневый)
1. [Шаг 1]
2. [Шаг 2]
3. [Шаг 3]
```

### 5. Правила

- **Timeboxed**: не уходи в бесконечный ресерч — достаточно 5-10 поисковых запросов
- **Приоритизируй**: опенсорс > статьи > Stack Overflow
- **Актуальность**: предпочитай источники 2024-2026 года
- **Практичность**: фокус на том, что реально применимо в нашем стеке
- **Не дублируй**: если в проекте уже есть решение — укажи на него
- **Результат в чат**: выведи саммари прямо в чат, чтобы можно было сразу передать агенту на разработку

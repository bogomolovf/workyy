# Настройка Cursor AI для команды Workyy

## 🎯 Цель

Этот документ описывает как настроить и использовать Cursor AI для эффективной командной разработки в проекте Workyy.

## ✅ Что уже настроено

Проект уже подготовлен для работы с Cursor AI:

- ✅ `.cursorrules` - Правила для ИИ
- ✅ `.cursor/knowledge/` - База знаний проекта
- ✅ `.cursor/prompts/` - Хранилище хороших промптов (команда добавляет сюда полезные промпты)
- ✅ `.cursor/commands/agents/` - Агентские команды
- ✅ `.cursor/commands/tasks/` - Команды задач
- ✅ `.cursor/TEAM_WORKFLOW.md` - Полное руководство

## 🚀 Быстрая настройка (5 минут)

### Шаг 1: Установи Cursor

1. Скачай последнюю версию с [cursor.com](https://cursor.com)
2. Установи и запусти
3. Проверь обновления: `Help → Check for Updates`

### Шаг 2: Открой проект

```bash
cd workyy-fullproject-stable
cursor .
```

Cursor автоматически прочитает `.cursorrules` и начнет использовать правила проекта.

### Шаг 3: Проверь загрузку команд

✅ **Команды уже добавлены в репозиторий!**

Все команды находятся в `.cursor/commands/` и автоматически загружаются.

1. Открой Settings: `Ctrl+,` (или `Cmd+,` на Mac)
2. Перейди в "Rules and Commands"
3. Убедись что "Import Claude Commands" включено (зеленый переключатель)
4. Команды должны появиться в разделе "Project Commands"

**Доступные команды:**

- `/review-pr` - Проверка Pull Request
- `/create-test` - Создание тестов
- `/check-architecture` - Проверка архитектуры
- `/resolve-conflict` - Разрешение конфликтов
- `/prepare-prod` - Подготовка к продакшну
- `/analyze-performance` - Анализ производительности
- `/check-security` - Проверка безопасности
- `/create-docs` - Создание документации
- `/suggest-improvements` - Предложения по улучшению
- `/explain-code` - Объяснение кода

### Шаг 4: Изучи базу знаний

Прочитай ключевые файлы:

- `.cursor/knowledge/architecture.md` - Архитектура
- `.cursor/knowledge/patterns.md` - Паттерны кода
- `.cursor/TEAM_WORKFLOW.md` - Процессы работы

Используй Cursor Ask для изучения:

```
"Объясни архитектуру проекта Workyy"
"Покажи примеры паттернов кода"
```

## 📖 Основные возможности

### 1. Режимы работы Cursor

#### Ask (только чтение)

**Когда использовать:**

- Изучение кода
- Поиск информации
- Понимание архитектуры

**Пример:**

```
"Как работает синхронизация канвы через WebSocket?"
"Где находится логика выполнения SQL узлов?"
```

#### Agent (Ctrl+I) - Автономная работа

**Когда использовать:**

- Разработка новой функциональности
- Рефакторинг
- Создание тестов
- Разрешение конфликтов

**Пример:**

```
"Создай компонент BoardList следуя паттернам из apps/web/src/components/"
```

#### Manual - Прямое редактирование

**Когда использовать:**

- Точный контроль изменений
- Мелкие правки
- Когда нужна полная уверенность

### 2. Пользовательские команды

Используй команды через префикс `/` в чате:

```
/review-pr для проверки моих изменений

/create-test для apps/realtime-server/src/services/boardService.ts

/check-architecture для текущей ветки
```

### 3. Специализированные агенты

#### Code Reviewer Agent

```
/code-reviewer

Проверь PR #123:
- Особое внимание на безопасность
- Проверь производительность
```

#### Test Generator Agent

```
/test-generator

Создай тесты для [компонент]:
- Покрой все сценарии
- Включи edge cases
```

#### Migration Helper Agent

```
/migration-helper

Проверь миграцию [название]:
- Безопасность
- Обратная совместимость
```

## 🔄 Ежедневный workflow

### Утро: Синхронизация

```bash
git checkout main
git pull
pnpm install
```

Используй Cursor Ask:

```
"Покажи что изменилось в main за последние коммиты"
```

### Работа над задачей

1. **Планирование** (Ask):

   ```
   "Как работает [компонент]?"
   "Где находится [функциональность]?"
   ```

2. **Разработка** (Agent):

   ```
   /develop-feature

   Название фичи: [НАЗВАНИЕ]
   Контекст задачи: [ОПИСАНИЕ]
   Требования: [СПИСОК]
   ```

   Или активируй агента:

   ```
   /developer

   Создай [фича]: [ОПИСАНИЕ]
   ```

3. **Тестирование** (Test Generator Agent):

   ```
   "/create-test для текущего файла"
   ```

4. **Проверка** (Code Reviewer Agent):
   ```
   "/review-pr для проверки моих изменений"
   ```

### Вечер: Коммит и PR

```bash
git add .
git commit -m "feat(web): add user profile"
git push origin feature/my-task
```

Используй Code Reviewer Agent перед созданием PR.

## 📝 Промпт-инжиниринг

### Структура хорошего промпта

1. **Контекст**: Что нужно сделать
2. **Требования**: Конкретные требования
3. **Шаги**: Пошаговые инструкции
4. **Примеры**: Ссылки на существующий код

### Используй команды

Используй команды Cursor для основных задач:

- Новая фича → `/develop-feature`
- Исправление бага → `/fix-bug`
- Рефакторинг → `/refactor`
- Код-ревью → `/code-review`

Или активируй агента и опиши задачу:

- Разработка → `/developer`
- Код-ревью → `/code-reviewer`
- Тесты → `/test-generator`

### Примеры хороших промптов

✅ **Хорошо:**

```
Создай компонент BoardList:
1. Изучи существующие компоненты в apps/web/src/components/
2. Следуй паттернам из .cursor/knowledge/patterns.md
3. Используй TypeScript строгие типы
4. Добавь тесты
5. Проверь что линтер проходит
```

❌ **Плохо:**

```
Создай компонент
```

## 🤝 Командная работа

### Code Review

1. **Разработчик** использует Code Reviewer Agent для самопроверки
2. **Коллега** ревьюит через Code Reviewer Agent
3. После апрува - мердж

### Синхронизация знаний

1. **Экспортируй важные чаты** после сложных решений
2. **Обновляй базу знаний** в `.cursor/knowledge/`
3. **Делитесь промптами** которые работают хорошо

### Еженедельные синхронизации

- Code Review Session через Cursor
- Архитектурный ревью через Cursor Ask
- Обновление документации

## 🚨 Частые проблемы

### Агент генерирует неправильный код

**Решение:**

- Будь более конкретным в промпте
- Указывай примеры из существующего кода
- Используй команды из `.cursor/commands/` (через префикс `/`)

### Конфликты при слиянии

**Решение:**

```
/resolve-conflict для файла [название]
```

### Не понимаю как работает код

**Решение:**

```
Используй Cursor Ask:
"Объясни как работает [компонент]"
"Покажи где используется [функция]"
```
